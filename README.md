# Image to Model AR

A minimal browser-based image-target AR website. Put a target image in `public/targets/` and a `.glb` model with the same filename in `public/3d/`. When the target is recognized, its matching model appears on top of the target and disappears when tracking is lost.

## Requirements

- Node.js 18 or newer
- A phone with a supported modern browser and camera
- HTTPS when hosted (localhost is allowed for local development)
- Internet access for the MindAR and A-Frame CDN scripts in this starter

## 1. Add matching files

Example:

```text
public/
  targets/
    coffee.jpg
    robot.png
  3d/
    coffee.glb
    robot.glb
```

The filename before the extension must match, case-insensitively. Prefer `.glb` models. If using `.gltf`, include its referenced `.bin` and texture files at paths the glTF expects.

## 2. Generate the target/model manifest

```bash
npm install
npm run manifest
```

The script pairs files and prints the required target order. The target order is alphabetical by image filename.

## 3. Compile the images into MindAR format

MindAR cannot use ordinary JPG/PNG files directly as its runtime image-target database. Compile all images into one `.mind` file:

1. Open the official MindAR target compiler: https://hiukim.github.io/mind-ar-js-doc/tools/compile/
2. Upload only the target images listed in the `npm run manifest` output, in exactly that printed order. Images without a matching model are skipped and must not be included in the compiled target set.
3. Compile and download the resulting `targets.mind`.
4. Save it to `public/targets/targets.mind`.

If you add, remove, or rename any target image or model, regenerate the manifest and compile a new `targets.mind` using the complete matched image set in the new printed order. The index order in the compiled file must match the manifest.

## 4. Run locally

```bash
npm run start
```

Open the local URL shown by Vite. For testing on a phone, the phone must reach the development server; camera permissions may require HTTPS depending on how you expose it. For public deployment, deploy the built site to an HTTPS host.

## 5. Build for deployment

```bash
npm run build
npm run preview
```

Deploy the generated `dist/` directory to any static host that supports HTTPS.

## 6. Hosting on GitHub Pages

1. Push this repository to GitHub.
2. In your GitHub repository, go to **Settings** → **Pages**.
3. Under **Build and deployment** → **Source**, select **GitHub Actions**.
4. The automated workflow (`.github/workflows/deploy.yml`) will build and publish your site at `https://<username>.github.io/<repo-name>/`.
5. Open that link on your phone. Because GitHub Pages provides HTTPS, camera permissions and WebAR will work directly!

## UI and behavior

- Start Camera opens the AR scanner.
- Matching image detected: corresponding model appears.
- Image lost: model is hidden.
- Exit stops the AR session and returns to the start screen.
- No accounts, database, manual placement, or persistent anchors are used.

## Adjust model placement and scale

`npm run manifest` generates `public/config/targets.json`. You can edit each target entry after generation:

- `position`: default `0 0 0`. The model sits flush on the target plane.
- `rotation`: default `0 0 0`.
- `scale`: default `0.2 0.2 0.2`. Adjust this to fit your model's units and size.

If you rerun `npm run manifest`, those values are regenerated to defaults, but existing settings are preserved by target stem name.

## Important notes

- This is image-target AR: the target must remain visible for the model to remain tracked. When the target is lost, the model is hidden as requested.
- The model is attached to the target plane, not placed on a floor or world-locked. Tracking smoothing is enabled; stronger smoothing can reduce jitter but may add some pose lag.
- Choose images with rich texture, edges and contrast. Plain logos, repetitive patterns, glare, blur and low light reduce tracking quality.
- A model may face the wrong way or be too large/small depending on how it was authored; adjust `rotation` and `scale`.
- MindAR's compiled target file and image list must use the exact same order.
- This starter references A-Frame and MindAR from CDNs. For offline or stricter production deployments, vendor and pin the dependencies locally.


## Camera background and tracking stability

The scene is configured with a transparent WebGL renderer so the live camera feed can show through. MindAR's pose filter is enabled with conservative smoothing values to reduce visible jitter. Smoothing trades a little responsiveness for steadier motion; it cannot remove all movement caused by blurry targets, poor lighting, camera autofocus, or low-texture images.

For best tracking:
- Use a sharp, matte, detailed target image.
- Keep the full image visible and avoid glare.
- Ensure the image is large enough in the camera view.
- Test on the actual mobile browser/device; camera and WebGL behavior varies by device.


## Tracking stability and grounding

The scene uses MindAR's native One Euro Filter (`filterMinCF: 0.001`, `filterBeta: 10`) for balanced, smooth tracking:
- `filterMinCF: 0.001`: suppresses micro-jitter and camera noise when the target/camera is still.
- `filterBeta: 10`: smoothly responds to movement while filtering out hand tremors and jitter, preventing both shaking and levitation lag.
- Automatic local bounding-box alignment ensures that the model's base sits flush on the target surface instead of floating above it or clipping into it.

## Wall or floor target

Set `surface` on each target in `public/config/targets.json`:

```json
{
  "name": "targets",
  "modelUrl": "/3d/targets.glb",
  "targetIndex": 0,
  "surface": "floor",
  "position": "0 0 0",
  "rotation": "0 0 0",
  "scale": "0.2 0.2 0.2"
}
```

- `"surface": "wall"`: for vertical posters or targets mounted upright on a wall.
- `"surface": "floor"`: for targets lying flat on a table or floor. Rotates the model 90 degrees around X and automatically aligns the lowest point of the model's geometry to rest directly on the target plane with zero levitation.

## Model animation

If a `.glb` contains embedded animation clips, an Animation Play/Pause button appears while that target is tracked. Models without animation do not show the button. If the source model has no animation tracks, export it again from your 3D editor with the desired animation included in the GLB.
